# 2.0产品与数据设计

## 边界与阶段

一期交付可运行的统一Web核心，提供大盘/个股/板块入口、排名、事件回测与持久化账号；原生包复用同一套Vue产物。真实采集与AI接入是进入实盘阶段的前提，不能用模拟填充冒充上线。

当前已开始阶段B的最小数据闭环：5只白名单股票普通讨论标题、限量正文和未复权日线手动采样、规则分类、追加观察与隔离查询；不是完整阶段B验收。标题和正文使用独立来源及状态，不以另一模式补齐。首页真实入口的自然日范围和规则分类限制见 [数据源说明](DATA_SOURCES.md)。

| 阶段 | 范围 | 验收标准 |
| --- | --- | --- |
| A：当前研发版 | Vue、API、账号、自选、站内预警、模拟分析/回测、原生工程 | 可启动，可选择对象，可持久化，计算与隔离测试通过 |
| B：数据闭环 | 合规可用的帖子/行情源、交易日历、AI版本化分类、去重/质量与覆盖率 | 每个数能追溯至当时可用的原始记录；无样本显示缺失 |
| C：上线分发 | HTTPS域名、PostgreSQL、签名APK/EXE、同API跨端验收 | 三端同账号看到同一自选/预警；实机安装验证；不混演示/真实数据 |
| D：持续研究 | 收盘调度、资金代理、板块扩散、样本外研究、推送/更新 | 可重复事件回测，含交易成本、可成交性与样本外报告 |

## 统一入口

稳定ID采用交易所+代码：`XSHG:000001` 上证指数，`XSHE:000001` 平安银行。裸六位代码不得作为主键或唯一自动匹配条件。名称、拼音别名、带交易所代码均返回候选对象。股票、指数、板块、全市场共享 `Instrument`，组合由账号下标的关系组成。

大盘模式不能只使用某一个指数股吧。至少记录每个股吧的贡献、去重后作者数及样本覆盖，再结合宽度；“全A宽度代理”与“指数成分宽度”必须分开标记。板块使用按日期生效的成分表，不能用今天的成分回算历史（幸存者偏差）。自选组合先提供逐标的对照，未定义权重时不生成虚构组合综合分。

## 统一结果

目标展示综合指数、覆盖率、多空中性分布、有效帖子/评论/阅读、趋势、词频、信号原因、快照时间、数据来源与版本。演示范围为交易日，固定数据为2026-10-12至2026-11-06的20个模拟交易日；真实标题/正文采样目前使用明确标注的北京时间自然日，缺失日期不补零。真实行情单列最新观察时间，不生成空行情；正式交易日统计待完整交易日历接入。

当前结果综合分采用周期聚合；趋势为每日分；观察信号使用最新单日而非周期均值；排行榜为最新单日。这些不同窗口须在UI写明，不混称“今天”。

## 评分与统计

`opinion_score = 100 * bullish / (bullish + bearish)`，无方向样本时返回null。中性计入有效帖子分布，排除广告/重复/无法识别内容，另列排除数。70多、20空、10中性的多空分是 **77.78**，并非78.5。

初始权重：股吧多空35%、方向校准热度20%、赚钱效应20%、资金活跃15%、变化速度10%。仅对可用维度按权重重新归一；同时返回原始覆盖权重。覆盖率不同的分数不能直接作为跨对象强弱排序依据，生产排名应按一致口径分组。

热度不是方向；恐慌放量不能自动加成乐观。上线前用滚动历史分位数、方向条件及样本外标定确定热度和资金活跃维度。目前热度、宽度、变化速度均来自模拟夹具；资金活跃缺失。波动、换手、主动买卖只描述交易代理，不直接识别散户/主力身份。

方向一致性 `abs(bull-bear)/(bull+bear)*100`；分歧 `100-一致性`；中性占比单列。该分歧指标仅描述有方向样本内的平衡，不能替代基于作者、观点与时序的更完整分歧度。置信区间和最低作者数门槛需在真实数据接入时校准。

状态采用不重叠区间 `[0,20)` 极度恐慌、`[20,40)` 悲观、`[40,60)` 中性分歧、`[60,80)` 乐观、`[80,100]` 极度亢奋；样本不足单列，不显示50分。

## 数据关系

| 表 | 关键字段 | 保存策略 |
| --- | --- | --- |
| instruments | id / kind / exchange / code / aliases / scope | 全市场、指数、个股、板块统一目录 |
| posts | source+source_id / instrument_id / author_hash / published_at / first_seen_at | 平台帖子身份稳定，首次发现时间不可回填 |
| post_revisions | post_id / observed_at / content_hash / text / engagement | 每次内容或互动观察追加，不覆盖旧快照 |
| classifications | revision_id / classified_at / model_version / prompt_version / result | AI输出与规则输出区分，重新识别追加版本 |
| sentiment_snapshots | instrument_id / session_date / available_at / created_at / version / data_mode / metrics | 相同对象日期版本唯一，修订用新版本，不覆盖原值 |
| price_bars | instrument_id / session_date / available_at / open / close / data_mode | 当前开发版基础行情；生产须扩展行情版本、复权与成交限制 |
| collection_runs | instrument_id / started_at / finished_at / status / details | 每次采集的源状态、响应摘要、观察时间及纳入/筛除计数 |
| quote_observations | run_id / instrument_id / observed_at / bars | 真实未复权日线批次追加观察，不覆盖历史 |
| provider_queries | user_id / kind / query / started_at / observed_at / status / result | 妙想只读规范化结果追加，账号隔离，不注入情绪或回测 |
| users / auth_sessions | hash / token_hash / expires_at | Argon2密码哈希，随机会话仅存token哈希，退出撤销 |
| watch_items | user_id / instrument_id | 账号隔离且重复添加幂等 |
| alert_rules | user_id / instrument_id / metric / threshold | 阈值0–100；当前仅站内查询 |

SQLAlchemy模型为数据库草案及开发建表来源，当前无正式迁移工具；`create_all`不能升级已存在的表。生产启用前引入Alembic迁移并通过SQLite/PostgreSQL双数据库验证，不通过删除库升级。

后续表：按生效日期的板块成分、完整交易日历、逐条质量排除、信号事件、回测运行及标签、预警事件/发送去重、日报、组合权重、迁移版本。

## 采集与识别管线（接入阶段）

1. 来源适配器明确许可、频率、分页与重试，保存抓取时间、发布时间、来源URL/ID；遇到拒绝、限流或登录要求停止并记录，不绕过限制。
2. 正文标准化去重；按内容、作者、时间窗口降权。点赞/评论只做有上限的权重，不能让单账号刷屏支配指标。分类训练/回测需要先抽样人工标注，识别广告、引述、反讽和否定。
3. AI结果使用结构化校验，输出方向、行为标签、质量标记、证据片段；低置信度进入复核或未知类，禁止默认为中性后混入准确率。记录模型、提示与规则版本、耗时、费用和分类完成时间。
4. 聚合时 `published_at <= cutoff` 且 `first_seen_at / observed_at / classified_at <= cutoff`；不能只按帖子的标称发布时间取数。当前真实标题/正文查询已经连接内容去重与每天每位作者3条封顶，任务由CLI手动运行，尚未配置线上调度。正文较长且可能提及多只证券，规则尚不具备实体归因、反讽和引述识别能力。
5. 增量生成不可变快照并保存样本ID集合/摘要、贡献股吧、排除率与有效作者数；演示、回填研究和实盘可交易信号使用隔离命名空间。

## 事件回测

当前可运行引擎：某日收盘后可用快照分数≥阈值，下一交易日开盘进入，第1/3/5/10交易日收盘退出。每个周期独立排除重叠持有区间；末端价格未成熟、价格晚于可用截止时间或信号迟于入场可用时间的样本剔除。显示样本数、平均毛收益、上涨比例、Wilson95%区间。

不能把该模拟胜率当作真实预测能力。当前按09:30开盘时间核验信号必须提前可用。生产还需补充：停牌/涨跌停无法成交、交易日历、手续费/滑点、复权与退市、行业基准超额收益、按时间分组的样本外划分、多重试验控制。阈值优化只能用训练区间；测试集保持锁定。当前数据每个对象只有20日，不足以评估任何预测价值。

## 信号定义与优先级

当前规则包括看多/看空≥80%、前日看空≥60%且当前低于50%、看多单日上升≥5个百分点、看多≥80%且近3日涨幅≤1%、价格跌而看多增。它们是开发阈值，需真实样本标定，不称“AI预测”。

重点后续：低位情绪升温需要滚动价格分位；反向指标需要一致性、价格动量衰减与流动性；热门异动需要相对同对象历史的异常讨论量，避免大股吧天然占优；资金分歧必须标注代理来源；板块扩散需同步成分和足够覆盖率。

## 收盘复盘与三端同步

服务端按Asia/Shanghai和正式交易日历在收盘后运行采集→分类→快照→信号→日报链，幂等键为交易日+版本。每步记录状态和失败原因，数据过期时不重发旧信号。任务锁、失败重试与通知去重持久化，不依赖用户手机常驻。当前未启用此调度；“情绪复盘”按钮仅生成模拟模板摘要。

统一账号同步只依赖API与数据库；网页/Capacitor/Tauri客户端不直接连接数据库，不内嵌采集任务或AI密钥。原生壳使用构建时HTTPS API地址，Web同源代理。后续通过版本化API与数据库迁移保证旧客户端可兼容，再实施签名更新。
